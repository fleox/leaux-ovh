AgentCMS, le CMS statique que mon agent sait piloter

De l'hébergement à la mise à jour du site et de ses contenus, AgentCMS confie tout le pilotage à votre agent IA, en une simple conversation.

Frédéric Leaux24 octobre 20264 min de lecture

AgentCMS est un CMS statique que votre agent IA sait piloter. C'est une admin façon WordPress qui tourne dans le navigateur et publie du HTML pur sur n'importe quel hébergeur statique. Pas de serveur, pas de PHP, pas de base de données à patcher.

Ce blog tourne dessus : le contenu vit en Markdown dans un dépôt GitHub privé, et le site est servi par GitHub Pages.

La démo

Démo d'AgentCMS, version anglaise.

Pourquoi AgentCMS

Le projet tient sur trois idées.

  • Rien à faire tourner. Le site public n'est que des fichiers : HTML, CSS et images. Il n'y a ni serveur ni plugin à patcher, ni base de données à sécuriser. C'est rapide partout, et l'hébergement est souvent gratuit.
  • Vos données, votre hébergement. Le contenu vit où vous le décidez. Il n'y a ni service AgentCMS, ni compte à créer, ni enfermement.
  • Pensé pour les agents. Tout ce que fait l'admin existe aussi en ligne de commande, avec une sortie JSON. Des skills prêtes à l'emploi couvrent Claude Code, Codex, Cursor et Hermes.

Votre site, piloté en une phrase

Dans Claude Code, deux commandes installent le plugin :

/plugin marketplace add fleox/agentcms
/plugin install agentcms@agentcms

Ensuite, il suffit de demander :

Installe un nouveau site AgentCMS sur GitHub Pages.

L'agent demande où stocker le contenu et où héberger le site, puis vous guide pour chaque token ou clé. Les secrets ne passent jamais par le chat.

Une fois le site en place, le back-office devient une conversation : écrire et publier un article avec ses photos, changer de thème, ajouter un favicon, activer le flux RSS. L'agent suit les mêmes règles et produit le même résultat que l'admin.

Le thème que vous regardez a été construit et installé de cette façon.

Et si vous préférez sans agent, une commande lance l'admin sur votre ordinateur, avec un assistant d'installation :

npx -y @agent-cms/agentcms serve

Comment ça marche

L'admin est le seul composant qui s'exécute. Quand vous cliquez sur Publier, elle lit le contenu et génère la page avec le thème actif, directement dans le navigateur. Elle envoie ensuite le HTML et les listes qui en dépendent, et seulement ce qui a changé.

Le lieu de stockage du contenu et l'hébergement du site sont deux choix indépendants. Pour le contenu :

  • Fichier SQLite : le choix par défaut, le plus simple pour un seul propriétaire, chiffré sur votre propre hébergement.
  • Markdown dans Git : pour les équipes, chaque changement est un commit et chaque rédacteur utilise son propre token GitHub ou GitLab.
  • Firebase : pour travailler à plusieurs en temps réel.
  • Ce navigateur : pour essayer, seul.

Pour le site : GitHub Pages, Cloudflare Pages, GitLab Pages, tout hébergeur déployé depuis Git comme Netlify ou Vercel, les buckets compatibles S3 (AWS, R2, OVH, Scaleway), un dossier local ou un simple ZIP.

Ce qu'on y trouve

  • Écriture : un éditeur par blocs, des articles, pages, catégories, tags et menus, une médiathèque qui génère les images WebP, et un import Markdown et WordPress.
  • Publication : des URL propres, le nettoyage automatique des anciens chemins, et un seul commit par action sur les hébergeurs Git.
  • SEO : balises canoniques, Open Graph, sitemaps, flux RSS, recherche statique et sites multilingues.
  • Extensions : 5 thèmes et une douzaine de plugins inclus, des hooks à la WordPress, et des thèmes et plugins livrés en simples ZIP, installables sans recompiler l'admin.
  • Sécurité : les secrets restent dans le navigateur de chaque rédacteur ou dans le fichier d'identifiants du CLI, jamais dans le site ou le dépôt. Les bases SQLite sont chiffrées en AES-256-GCM par défaut.

Par rapport aux autres outils

  • WordPress offre la même admin visuelle, mais avec un serveur et une base de données à maintenir, et un site public qui n'est pas statique.
  • Les générateurs de sites statiques produisent aussi des fichiers, mais sans admin visuelle pour les rédacteurs, et avec un pipeline de build à mettre en place.
  • Les CMS headless ont une admin, mais il faut un front à construire et un serveur à maintenir, ou un service SaaS où vit le contenu.

AgentCMS combine l'admin visuelle et le site statique, sans serveur ni build à gérer. Et un agent peut le piloter entièrement.
